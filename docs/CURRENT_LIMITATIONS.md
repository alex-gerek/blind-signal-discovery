# Current limitations and independent review record

Reviewed on 2026-11-26: `development/v0.3` at `e1bd520`, same tree as public `main` at `7e72a12`. This record preserves the findings behind the documentation correction. The issues below are **open** unless explicitly stated otherwise. Documentation and version alignment do not fix them.

## Implementations and verification scope

The Python Local Measurement Workstation wraps the three-scale detector and adaptive managers. The browser demo in `docs/workstation/index.html` is a separate single-scale implementation with different sampling, window length, RNG and noise models. A shared version series or model label is not evidence of numerical equivalence.

The author recorded 87/87 Python tests passing at `986dd46`. An independent review at `e1bd520` ran 70 selected Python tests successfully, with two selected tests deselected, in 261.09 seconds. The selected files were `test_adaptive_regime.py`, `test_phase2b.py`, `test_detector_v2.py`, `test_coincidence.py`, `test_regime_monitor.py`, `test_vetoes.py`, `test_bsd.py`, and `test_codex_audit_fixes.py`. The selection excluded `result_serialization_and_end_to_end` and `workstation_export`; it did not run every repository test file. The harness disabled bytecode/cache/log writes, blocked filesystem mutation and networking, and blocked O3 manifest access. This was not a full 87-test rerun or an end-to-end GUI validation. Console evidence was retained in the review conversation; no raw log artifact was saved.

Browser checks executed the actual inline functions in Node.js with an in-memory DOM and stubbed canvas calls. WAV checks supplied a decoded synthetic array through a stub AudioContext; they establish the decimation error, not real-browser codec behavior. Python upload/aggregation checks used in-memory mocks. None of these checks involved O3 input data or new scientific performance studies.

The browser currently stores only nominated candidates, including an empty candidate list during unavailable calibration; it does not implement Python's full diagnostic-candidate preservation. Its count-based `VALIDATED_SYNTH_COUNT` export label is not the Python `VALIDATED` screening procedure. Browser pink-noise shaping is pure 1/f, unlike the Python knee/random-slope generator. These differences need their own protocol, tests and clear scope; do not transfer Python reference values or test claims to the browser.

## Assumptions and work not verified

- Exchangeability underlies conformal guarantees. Linear autocorrelation screening, an estimated effective sample size, and a `VALIDATED` label do not prove it for arbitrary sensors. Dependence-adjusted Beta intervals are heuristic.
- Sidak channel budgeting requires channel-dependence assumptions. Time slides of STFT matches do not supply significance for waveform-correlation-confirmed events.
- The fallback named RNG stream mapping can collide: names `ab` and `ca` map to the same stream code for the same master seed. Repeatability alone does not establish independence or data separation.
- Historical adaptive recovery, sensitivity, exposure and time-slide FAR have not been recomputed with the audited code. Preserve original outputs and run any follow-up into a fresh location. See the [erratum](AUDIT_ERRATUM_47a5475.md).
- The previous manual Python verification saved no UI export bundle. It is an observation/control record, not a complete replay artifact.
- A fresh installation, complete interactive GUI behavior and general real-data performance were not verified in this review. No candidate is established as novel or astrophysical.

## Input-validation follow-up (2026-11-26, working tree based on `99fce40`)

- **L02 implemented:** Browser CSV rejects nonfinite, missing and malformed data rows, constant signals, invalid sampling rates and non-increasing/nonuniform time axes. Supported schema is one value column or two columns (`time_seconds,value`), optional header, no quoted fields. Python CSV retains standard CSV quoting and explicit index/name column selection, rejects malformed rows with line/column detail, and checks supplied rate against time metadata. NPY must be safe, real numeric data; object/pickle, complex and text arrays are rejected rather than coerced.
- **L03 input checks implemented:** Browser runs reject identical file SHA-256 hashes, mismatched effective sampling rates and overlapping comparable CSV time intervals. Export metadata now records per-input hashes, sample counts, transformation details and the separation audit. Without timestamps, status remains `UNVERIFIED_EXTERNAL_CHECK_REQUIRED`; distinct hashes are not proof of independence. CSV time columns are interpreted in a user-declared common reference. Python rate/overlap checks also apply across different detector names; overlapping recordings are not relabelled as disjoint.
- **L05 implemented:** Each Python upload gets a newly allocated directory and retains its original basename. Concurrent uploads cannot overwrite each other; reserved filenames and invalid/empty payloads are rejected. The basename remains available to existing holdout checks. Temporary uploads remain under `.tmp/uploads`; automatic retention/cleanup is not introduced.
- Both interfaces clear stale results after a rejected new measurement. Browser errors are displayed and exports disabled; the selected window is retained on successful reruns. Browser calibration parameters are checked before rank loops, including integer-representability limits.
- **Still open:** L01 WAV aliasing (stride-decimation mathematics unchanged, with an explicit preprocessing warning), L04 abstention metrics, L06 seed-zero/synthetic configuration provenance, L07 full numeric precision and L08 exposure-aware v0.2 reruns. Mono WAV is required in the browser; use the Python channel selector for multichannel input. This follow-up does not certify WAV frequency candidates or establish browser/Python equivalence.

Validation passed for 34 distinct pytest cases across the final selections, including three existing ingestion/WAV export integration checks and a wrapper running six Node browser scenarios. The tests are `tests/test_input_validation.py` and `tests/test_browser_input_validation.js`; this was not a full-suite rerun. Test fixtures use synthetic metadata instead of reading the O3 manifest. Final outcomes are recorded in [research history](RESEARCH_HISTORY.md).


## Abstention/export follow-up (2026-11-26, working tree based on `8053741`)

- **L04 implemented for current output:** The UI uses availability-conditioned noise false-alarm fractions and injection efficiency, with eligible counts and available exposure. Zero eligible windows/injections yield `null` and an explicit unavailable status. Injection records distinguish `DETECTED`, `MISSED` while available, and `ABSTAINED`. Available misses and abstentions have separate lists. Wilson intervals are diagnostic and retain their independence assumption.
- **Compatibility:** Python legacy `negative_control_far`, `detection_efficiency`, `positive_injections_missed` and `missed_records` retain their former all-window/non-detection meanings, including abstentions where applicable; `legacy_metric_semantics` explains this. A legacy all-window zero is not a conditional FAR estimate. Downstream consumers must use the new available-denominator fields and statuses for that purpose. No older historical file is rewritten.
- **L07 implemented additively:** CSV/JSON schema v2 preserves old rounded numeric keys and adds `*_full_precision` values for original score/threshold comparisons, candidate p-values and candidate coordinates. `None` remains `null` in JSON and blank in CSV. Nonfinite decision inputs are rejected. Old records without precise values are not reconstructed. Empty CSV exports retain headers. Additional fields require readers to select columns by name rather than assume a fixed column count.
- Python saved bundles and Streamlit downloads share `build_workstation_report` and `build_workstation_csv`. JSON includes diagnostic candidate records; the availability timeline includes full-precision active-channel inputs. Diagnostic nominations and accepted decisions remain separate during abstention. Browser summaries, injection tables and navigation distinguish abstention from misses, and exported ground-truth accounting uses the same denominators as the UI.
- Detector/calibration statistics, veto decisions and waveform preprocessing were not changed in this output step. L01 WAV aliasing, L06 seed-zero/synthetic provenance and L08 historical exposure reruns remain open. A full-precision decision record is not by itself a complete run-reproduction bundle.

## WAV preprocessing follow-up (2026-11-26, working tree based on `8fab987`)

- **L01 implementation corrected:** Browser WAV stride decimation is replaced with a fixed-parameter centered Kaiser-sinc rational FIR resampler to exact 512 Hz. Passband/stopband tone controls, the old 400 Hz alias reproduction, timing, duration, input immutability, ratio-resource errors and mixed-source-rate file workflow passed. See the [design and validation record](browser_wav_resampling_protocol_2026-11-26.md) for the prespecified criteria and bounded outcomes.
- Original RIFF/WAVE metadata are inspected separately from Web Audio's decoded sampling rate. Exported provenance records both rates, decoder conversion, filter identity/beta/cutoff/support, exact output rate/count/duration and padding warnings. Mono little-endian RIFF/WAVE at original rate >=512 Hz is required; browser decoder support still governs codecs. Synthetic generation and CSV preprocessing are unchanged.
- **Scientific limits:** This is an offline centered transform with disclosed future-sample use; within-file filtering can correlate adjacent windows. Each input file is filtered separately. Edge windows are disclosed rather than automatically removed, so independent real-data false-alarm validation remains necessary. The useful resampled band is 0–192 Hz, with a 192–256 Hz transition; near-Nyquist amplitude is intentionally attenuated. The first/last approximately 47 ms have padding effects. Tested stopband residuals were below a -70 dB amplitude criterion on specified synthetic tones away from edges; finite attenuation is not complete alias elimination or a general detector guarantee. Historical stride-decimated WAV outcomes require separate reruns and must not be relabelled as new-filter results.
- Fifteen Node scenarios and three independent SciPy reference cases passed. Native browser codec/rendering behavior has not been manually verified; tests use synthetic WAV bytes and decoder fixtures. L06 seed-zero/synthetic provenance, diagnostic-cluster preservation differences and L08 historical exposure reruns remain open. No O3 input or historical artifact was used or overwritten.
